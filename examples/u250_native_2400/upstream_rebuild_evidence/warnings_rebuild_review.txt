CDC report: 5 critical, 20 warnings, 1 informational
-------------------------------------------------
CDC-6 (4): three-bit JTAG FIFO Gray pointers use two-stage ASYNC_REG
synchronizers. Independent bus-skew constraints pass. Correctness depends
on the Gray counter and FIFO protocols; timing exclusion alone is insufficient.
CDC-26 (16): JTAG dual-clock LUTRAM read/write collision diagnostics. The FIFO
full/empty protocol controls ownership; arbitrary cross-clock RAM access is
not qualified by this report. Management accesses are separate from native DMA.
CDC-10 (5 critical): four JTAG reset paths combine logic before asynchronous
reset synchronizers; one Native PHY en_vtc readiness/control path combines
logic before its RIU-domain two-stage synchronizer. These are retained
experimental limitations, including potential reset glitches and VTC changes
during transitions. Stable management controls, reset release and VTC behavior
need independent hardware qualification. No waiver or severity downgrade was
applied to claim a clean CDC report.
CDC-9 (1 info): asynchronous reset with ASYNC_REG synchronization.

Methodology report: 17 warnings, 3 advisories, no critical warnings
----------------------------------------------------------------
LUTAR-1 (1): JTAG reset-combining LUT drives asynchronous preset/clear; this
is the reset-glitch concern above and remains unresolved.
SYNTH-6 (16): FIFO BRAM output registers are implemented in fabric rather
than merged into the RAM blocks. Routed timing passes; this is an optimization
diagnostic, not a proof of functional memory operation.
CLKC-58 (3 advisories): Native PLLE4s have no explicit LOC; actual connected
Native resources and clocks were placed/routed in this device. Placement and
clock behavior still need physical calibration validation.

DRC report: 4 warnings, no errors or critical warnings
----------------------------------------------------
DCIRST-1 (4): inactive DDR1/DDR2 CKE and CS_n use SSTL12_DCI without a
DCIRESET primitive in those banks. All unused modules are held RESET_n low,
CKE low and CS_n high. This explains the intended inactive state; it does
not establish electrical behavior on a physical board. Channel-0 active
interfaces have no DCIRST-1 diagnostic in the fresh report.

DMA tests, 1 upstream DMA byte-enable test (24 subcases), 51 stream tests.
DMA tests cover addresses above 4 GiB, the final 64-byte word, all byte masks
with RMW, independent engines and stalls; they do not exercise 16 GiB of

simulation-only compatibility shim with pinned Migen; no synthesis sources
were changed by this shim. LiteEth was added only for upstream KCU105 test

The archived regression wrappers were executed from the isolated workspace
named in the logs; their ROOT is their original workspace parent. The portable
example checks are reproduced with python scripts/run_tests.py. Full upstream
regressions additionally require the pinned LiteEth checkout and the archived
write-only simulation shim, with repository paths set as in those wrappers.

Native/RDIMM limitations retained from the original delivery
---------------------------------------------------------
Installed SPD, registered command latency, RDIMM RCWs, CL17/CWL12, ODT/drive
settings and Native BITSLICE reset/RIU/VTC behavior have no hardware validation.
Native and reference MIG differ in REFCLK_FREQ/PLLCLK attribute interpretation
and RTT_WR settings; their equivalence is unproven. No autonomous calibration
or board programming was performed. External CSR initialization/training must
precede DMA admission. No calibration logs or measured throughput are claimed.
The 150 MHz x512 native interface has a 9.6 GB/s ceiling versus 19.2 GB/s
physical x64 DDR4-2400; that is an architectural limit, not measured bandwidth.
